## 3. Track Merging Effect（飛跡併合効果）評価用 2D ヒストグラムの実装

$\Lambda$ を再構成する陽子（proton）と各原子核（$d, t, ^3\text{He}, ^4\text{He}$）の間における TPC 飛跡併合効果（Track Merging Effect）を評価するため、$\Delta\phi^*$ vs $\Delta\eta$ の 2 次元ヒストグラム解析を実装。

### ① 計算式とパラメータ設定
$$\Delta\phi^*(R) = \phi_p - \phi_{\text{nuc}} + \arcsin\left(\frac{0.3\, q_p\, B_z\, R}{2 p_{Tp}}\right) - \arcsin\left(\frac{0.3\, q_{\text{nuc}}\, B_z\, R}{2 p_{T\text{nuc}}}\right)$$
$$\Delta\eta = \eta_p - \eta_{\text{nuc}}$$

- **磁場**: $B_z = 0.5\ \text{[T]}$
- **TPC 代表半径**: $R = 1.4\ \text{[m]}$（TPC 有効領域 $0.6\ \text{m} < R < 1.9\ \text{m}$ の中央値）
- **粒子電荷**:
  - 陽子 ($p$): $q_p = +1$
  - 重陽子 ($d$): $q_d = +1$
  - 三重水素 ($t$): $q_t = +1$
  - ヘリウム3 ($^3\text{He}$): $q_{^3\text{He}} = +2$
  - ヘリウム4 ($^4\text{He}$): $q_{^4\text{He}} = +2$
- **保護処理**:
  - $\arcsin$ の引数が $\pm 1$ を超えて NaN となるのを防ぐクランプ処理を追加。
  - $\Delta\phi^*$ を $[-\pi, \pi]$ の範囲に折りたたむラッピング処理を追加。

### ② アーキテクチャの統一（HistManager / YAML 管理）
プロジェクトの標準設計に合わせ、ヒストグラムの管理を YAML 定義および `HistManager` に統合。

1. **Maker の拡張** (`StMaker/StNuclearIdMaker/`):
   - `StNuclearIdMaker.h` / `StNuclearIdMaker.cxx` に `FillTrackMerging(Double_t dphiStar, Double_t deta, Int_t type)` を追加。
   - `HistManager::Fill("hDphiDeta_proton_<species>", dphiStar, deta)` 経由で Fill する実装を追加。
2. **ヒストグラム定義 YAML の更新**:
   - `config/hist/hist_auau3p85_anaLambdaNuclearId.yaml`
   - `config/hist/hist_auau13p5_anaLambdaNuclearId.yaml`
   - 軸定義 `DeltaPhiStar`, `DeltaEta`（200 bins, 範囲 $[-0.25, 0.25]$）を追加。
   - `hDphiDeta_proton_d`, `hDphiDeta_proton_t`, `hDphiDeta_proton_3He`, `hDphiDeta_proton_4He` を定義。
3. **解析マクロの更新** (`analysis/anaLambdaNuclearId.C`):
   - $\Lambda$ のシグナル質量領域（`isSig`）において、自己相関（娘粒子と原子核の track ID 一致）を除外した陽子-原子核ペアに対して `nuclearidMaker->FillTrackMerging(...)` を呼び出すよう実装。
   - `nuclearidMaker->WriteHistograms()` により出力 ROOT ファイル内の `true/` ディレクトリに自動保存。
