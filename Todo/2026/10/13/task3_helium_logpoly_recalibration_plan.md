# Task 3再校正計画: 広いdE/dx表示と共通係数による³He/⁴He校正

## 依頼と現状

ユーザーから、低剛性fit図の下段dE/dxが狭く³Heを確認できないこと、および最新PID曲線の⁴He中心が低Rで不自然に見えることを指摘された。前回の205点の補間校正を正しいと仮定せず、実際のpre-PID p/q×dE/dx分布で再検証する。

既存fit・PDF・校正YAML・試験ROOT・snapshotを保持し、新studyへ出力する。対象は3.85 GeV・2021 P24iyのみ。本投入・git操作・元統合ROOTの変更は行わない。

## 1. 下段dE/dxの表示修正

元のnσ図の表示範囲−8～+4を、各保存sliceの元校正中心・幅でdE/dxへ変換して下段にも使用する。保存軸0～120 keV/cmでclipし、上段と同じ物理範囲にする。log/linear、triton・³He・⁴He候補の成分を同じ範囲で確認できるようにする。

保存済みfitを再描画するだけで再fitしない。元studyと旧viewsのhash・入力fingerprintを前後照合し、`views_full_dedx/`へ別保存する。前回のmainconfはその後更新されているため、保存studyの来歴と現在のROOT実行用mainconfを明確に分ける。通常の厳密照合は維持し、表示専用の明示的opt-inに限りruntime mainconfの変化を許し、STAR/datasetと消費した設定全文を記録する。

## 2. 既存曲線の生分布上での検証

元統合ROOTの`true/hDedxP`をCOLZで表示し、従来式、現在の補間校正、元の独立fit点を重ねる。全R域と0.40～0.65を別panelで見る。元データのbinを勝手に切断・選別して「ピーク」と呼ばない。表示rebinやclipは設定・注記へ残す。

初期数値監査では、R=0.41直前の従来⁴He平均104.765 keV/cmに対し、校正domain開始時に82.021へ切り替わるため約−22.745 keV/cmの人工的段差を確認した。R=.405では従来106.058を使う。欠落fit binでもlegacyへ戻る段差があり、現在の曲線を検証済みの滑らかなPID関数と扱わない。

³Heの識別補助として、保存済み`true/hDedxP_3He_m2`等のTOF窓QAが存在するか確認する。TPCで切断された`hDedxP_4He`を中心・幅の独立測定の入力には使わない。TOFタグもcut・統計・混入の条件を明示し、無条件の真の核種ラベルと扱わない。

## 3. 解析コードと同じ関数形の係数fit

L=log10(R)、R=|p/q| [GeV/c]として、核種sの中心と幅を

```text
mu_s(R)    = c0_s + c1_s L + c2_s L^2 + c3_s L^3
sigma_s(R) = d0_s + d1_s L + d2_s L^2
```

で表す。³He/⁴Heの各中心4係数・幅3係数は複数R区間で共通とし、Rごとの独立free中心・幅は採用しない。前回の独立fit点への単純な回帰は初期値・比較にだけ使い、最終係数は生分布のjoint fit等で検証する。

Rごとの粒子数・smooth背景の規格化等は必要なnuisanceとして扱える。近傍triton/deuteron、非Gaussian tail、保存上限による切断、R bin内の中心変化、dE/dxのFloat16量子化を考慮する。dE/dx bin積分に基づく尤度を優先し、幅をbin中心評価だけで押し広げない。

中心順序・幅の正値・滑らかさ、背景model依存、初期値依存、低Rを除いた／含めたfit、保留R区間の再現、bin幅変更を確認する。単に見た目を滑らかにしたことをピーク位置の正しさと同一視しない。Gaussianの肩を別核種として過剰に断定しない。

## 4. 係数の保存・適用判断

係数・domain・fit範囲・背景と境界・共分散・品質・原本hashを新しいYAML/JSONへ保存する。元の共有`NuclearIdDeDxVsMom.h`は変更しない。

生分布・残差・独立検証で候補が支持される場合、3p85専用providerで解析式を直接評価する方式に導入し、現在の補間YAMLとlegacyへの切り戻しを保持する。十分に拘束できないR域や式の不適合が残れば、その限界を報告し、無理に「問題ない」として本番化しない。nσのcut上限は中心・幅とは別で、変更する場合は明示する。
